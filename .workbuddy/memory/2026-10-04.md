## 三个$\omega$ 的正确区分（commit edeb7b3 + c8f7d06，重要更正）

我一度把 825 题面的「幅值穿越频率 $\omega_c$」判成「与课本截止频率 $\omega_c$ 符号冲突」，**是错的，用户一句「截止和穿越是一个东西吧」直接推翻**：

| 记号 | 定义 | 读什么 | 教材 | 825 题面 |
| :-- | :-- | :-- | :-- | :-- |
| $\omega_c$ | $\lvert G\rvert=1$ | **幅值**（过 0 dB） | 截止频率 | 幅值穿越频率（同一物） |
| $\omega_x$ / $\omega_g$ | $\varphi=-180°$ | **相位** | 记 $\omega_x$ | 两套记法都用 |
| $\omega_r,\omega_b$ | 谐振、带宽 | — | — | 未出现 |

- **截止频率 = 幅值穿越频率（gain crossover），名异实同**，题面与课本**无需转换**。
- $\omega_c$（幅值）与 $\omega_x$（相位）**是两个不同频率**。2010·5(2) 同题活证：$\omega_c\approx0.5716$（算 $\gamma$）$\ne$ $\omega_x=1/\sqrt2\approx0.707$（算 $h$）。
- **$\omega_g$ 与 $\omega_x$ 是同一个量**，但 825 内部两套记法混用（$\omega_g$: 2015/2016/2024/2025；$\omega_x$: 2010/2013/2014/2017/2019/2020/2021/2025；**2025 同年两种都有**）——是两套解析各自沿用不同教材习惯，不是青大规定。这才是唯一值得记的「习惯差异」。
- 本库口径：笔记统一 $\omega_x$；`05-3-8` 因讲 777 答案册口径统一 $\omega_g$（该页已有记号说明）；真题页各自原样不改。

**教训**：术语「名异实同」vs「量不同」极易混淆。判据是**定义式相同就是同一个量**（$|G|=1$），别看到两个名字就当冲突。

## 严重事故：跨区间替换吞掉正文（edeb7b3 → c8f7d06 修复）

替换 callout 时用「起始标记 → **远端**结束标记（如文末 `> 相关：`）」做区间替换，**中间几十行正文被整块吞掉**：05-4-3 从 197 行掉到 63 行，§5.4.6/5.4.7/设计参考/延迟/条件稳定/三边界全丢，两张配图也没了，而 `check-notes.ps1` 报「0 致命 0 待修」——**校验脚本不查内容缺失**。

- 修复：`git show <上一提交>:"路径" > 临时文件` 取回完整版（注意 `git show` 输出是 **LF**，要 `re.sub(r"(?<!\r)\n","\r\n")` 归一），只替换该 callout 自身到下一空行的小段。
- 脚本必加两条断言：**每个小节标题逐个断言存在** + **替换后行数 ≥ 替换前行数**。
- 推论：**行数/结构骤降超30% 一律先 `git diff --stat` 看清楚再 commit**；已 push 的误删要立刻 `git show` 上一提交恢复（本次隔了一笔才发现，靠的是 `wc -l` 与 `grep "^## "` 复核）。
- 补充坑：插入/替换后必查 **callout 内是否混入真空行**（`\r\n\r\n`），会把 callout 截断成两半、渲染成两个块。校验脚本查不出来，只能自己扫「callout 区间内真空行数 == 0」。
